    человек, поэтому `LOGIN_PER_MINUTE_PER_IP=20` оставлен без изменений.
  - sysinfo: реализован write-once + разрешение из панели, лимит поднят до
    конечных 6000/мин (см. `docs/knowledge/DECISIONS.md` DEC-014,
    `docs/knowledge/ERRORS.md` ERR-015). Синтетически проверено 800
    устройств; живой прогон остаётся в блокирующей задаче ниже.
- **Зависимости и ограничения:** не поднимать login-лимит «на всякий
  случай»; sysinfo-лимит конечный и не заменяет write-once защиту.
- **Связанные документы:** `docs/knowledge/ERRORS.md` ERR-014/ERR-015,
  `docs/project/API_REFERENCE.md` §1.3 и §2.15, `docs/SECURITY.md` §10.

## 3. Технический долг

Это известные ограничения, которые не обязательно требуют немедленного
спринта. Если пункт превращается в задачу — перенеси его в «К выполнению»,
а не дублируй.

- **Автотесты покрывают heartbeat rate limiting, sysinfo write-once,
  display name и audit log.** Остальные области и CI отсутствуют; расширение
  запланировано в `TODO-003`. Не добавляй фиктивный `pytest.ini` ради
  зелёного отчёта.
- **Rate limit — in-memory и per-process.** `python -m app` запускает один
  uvicorn worker; при нескольких workers/репликах лимиты умножатся, внешнего
  store нет. Не масштабировать processes без пересмотра лимитеров.
- **Naive UTC во всех слоях (SEC-012).** Компенсация — `parseUtc` на
  frontend. Менять только полной миграцией БД/API/UI, не точечно.
- **Audit log append-only, но не WORM.** Admin с доступом к БД/файлу может
  изменить строки; защита — права файла, хост и retention. Чтение — только
  admin, отдельной роли аудитора нет. См. DEC-017.
- **Нет `/metrics` и фонового мониторинга.** Health-check есть, метрик нет.
- **Rate limit только на login/heartbeat/sysinfo.** Остальные `/api/*` не
  throttled; это осознанное MVP-ограничение, но нагрузочный риск.
- **Discovery-очередь in-memory.** При рестарте необработанные события
  теряются; при переполнении (20 000) события дропаются.
- **Логи только в stdout/stderr.** Файла `logs/app.log` нет; ротация — на
  уровне systemd/Docker. Не добавляй файловый handler без решения по
  ротации.
- **Две исторические БД** (`data/base.db`, `data/pc-service.db`). Их нельзя
  сливать/переключать автоматически; риск «пустой панели» остаётся
  конфигурационным.
- **Frontend собирается, но Node в системе не установлен.** `npm run build`
  и `npm run lint` проверены 2026-10-28 с временным Node.js 22 из
  `/tmp`; `frontend/dist` gitignored, поэтому деплой обязан собирать SPA
  (`Dockerfile`) и не может полагаться на артефакт из репозитория.
- **Docker-путь не воспроизводим с чистого клона**, пока не выполнен
  `TODO-002`.
- **Права `address_book_permissions` управляются вне UI** до `TODO-009`.
